Credential login with NextAuth

Authentication is the process of verifying who a particular user is - verifying a user's identity. In this tutorial, we'll setup credential-based login - email and password - with NextAuth.

Project setup​

Accept and clone the template repository for this tutorial.

Install dependencies​

There are two new development tools we need to implement authentication:

  • next-auth - signin() and signout() with jwt token
  • bcrypt - hashing functions

The template repositories package.json includes dependencies next-auth and bcrypt so they will be included on the following install command:

npm install

Setup environment​

Copy the .env file you established in previous projects to the project root ( same level as src ). We will connect to your established database and add a new collection.

Add an environment variable AUTH_SECRET which is the key used to encode the JWT and encrypt things in transit. The following command will add the environment variable to your .env.local.

npx auth secret

jwt session​

To establish a login session, we'll use JSON web tokens.

authConfig​

Configure NextAuth to use jwt as the session strategy:

auth.config.ts
import { NextAuthConfig } from "next-auth";

export const authConfig: NextAuthConfig = {
  session: {
    strategy: "jwt",
  },
  providers: [],
};

When using JWT sessions, NextAuth stores session data in an encrypted, HTTP cookie. NextAuth provides the following to implement JWT session cookies:

  • signIn() - Creates a signed JWT session cookie
  • signOut() - Deletes the cookie
  • auth() - Verifies the JWT on each request
  • middleware - access the cookie to protect routes

signIn()​

await signIn("credentials", {
    email,
    password,
    redirect: false
});

signIn() runs your credential validation - the authorize() function - to check the password with bcrypt, generates the JWT and stores it in the cookie.

signOut()​

await signOut({ ridirectTo: "/" });

signOut() clears the JWT cookie which closes the session

auth()​

const session = await auth();

Each time you call auth() in a server component, it checks the session cookie of the incoming request and verifies its signature with your NEXTAUTH_SECRET. If the session token is valid, auth decrypts it and returns the user payload (username, email). In App Router, every server request contains the session cookie.

authorize()​

auth.ts is where we'll define the settings for our authentication. We set providers and session strategy in this config file. Then we import this info into our routes, middleware and components. This file includes settings and exports the route handlers for signup and login.

We set our provider to credentials. This is where you can also add OAuth, etc. as providers. authorize() looks up the user by email with a findOne() on the database and if the credentials match a user in the database we return the user object.

auth.ts

export const {
    handlers: { GET, POST },
    auth,
    signIn,
    signOut,
} = NextAuth({
    ...authConfig,
  providers: [
    CredentialsProvider({
      credentials: {
        email: {},
        password: {},
      },

authorize() runs during a login attempt using signIn("credentials"). It looks for the a matching user in the database and checks password hashes.
It returns a user object or null.

auth.ts
      async authorize(credentials) {
        const email = credentials?.email;
        const password = credentials?.password;

        if (!credentials) return null;

        try {
          await connectMongoDB(); 
          const user = await User.findOne({ email: credentials.email }).lean();

          if (user) {
            const isMatch = await bcrypt.compare(
              credentials.password,
              user.password
            );

            if (isMatch) {
              return {
                id: user._id.toString(),
                email: user.email,
                name: user.username,
              };
            } else {
              console.log("Email or Password is not correct");
              return null;
            }
          } else {
             console.log("User not found");
             return null;
          }
        } catch (error: any) {
          console.log("An error occurred: ", error);
          return null;
        }
      },
    }),
  ],
});

Implement users​

We learned from previous projects that to add users to our project means we need a schema to define what the data should look like and we'll need a signup form to add a new user. We'll also need a login form for existing users so we can verify their identity.

user model​

To implement authentication, we need to represent users. Each user will be represented as a:

  • username
  • email
  • password

We'll use the email as the unique identifier for each user. The password will be the security measure to verify identity. To implement users, we need a new collection of data. We have learned to create, read, update and delete items. We'll follow a similar path to create and verify users. First, let's create the model for a user.

Create a user schema with a username, email and password (and any other info you want to include) and construct a User model from the schema.

/models/UserSchema.js
import mongoose, { Document, Schema, Model } from "mongoose";

export interface IUser extends Document {
  username: string;
  email: string;
  password: string;
}

const userSchema = new Schema<IUser>({
  username: { type: String, required: true },
  email: { type: String, required: true },
  password: { type: String, required: true },
});

const User: Model<IUser> = mongoose.models.User || mongoose.model<IUser>("User", userSchema);
export default User;

We need to specify the data type of each field and whether it should be required or not. In this example, every field is required.

  • Setting required to true makes the field required for every User model.
  • Setting unique to true makes sure no other user has the same username or email.

create the endpoint for the signup request​

In the route.ts file for the signup route, on the POST request, use bcrypt to hash the password before adding it to the database:

app/api/signup/route.ts

export const POST = async (request) => {
  const {username, email, password} = await request.json();

  await connectMongoDB();
  const hashedPassword = await bcrypt.hash(password, 5);
  const newUser = {
    username,
    password: hashedPassword,
    email
  }
  try {
    await User.create(newUser);
  } 
 }
