Asynchronous JavaScript

Asynchronous programming:

  • enables your program to start a potentially long-running task while . . .
  • responding to other events, without . . .
  • waiting until the task has finished

Once that task has finished, your program is presented with the result.

why?

Why is asynchronous programming important in web programming?

JavaScript in the browser runs on a single thread (the call stack). If a task takes too long, the page would freeze and users couldn’t click, scroll, or type. Asynchronous code lets the browser start a long task and then come back to it later, without blocking everything else.

Examples:

  • Network requests: waiting for an API response (could be hundreds of ms or several seconds).

  • Timers: setTimeout and setInterval.

  • User input events: typing, scrolling.

  • I/O operations: reading files, accessing databases (on the server side).

asynchronous methods​

By using three asynchronous methods: callbacks, promises, and async/await, the program can continue running other code while waiting for the task to finish.

  1. Callbacks
  2. Promises
  3. Async/Await

fetching data example​

fetch("/api/products")
  .then(res => res.json())
  .then(data => console.log(data));
Send me all movies that match the query Bat?

Without async behavior, the whole page would freeze until the server responded.

  • Handling user actions You want a user to keep typing in a form while a background validation API call runs.

  • Animations and UI updates Browsers schedule these asynchronously so the interface feels smooth.

  • Servers (like Node.js) Node is built around asynchronous programming so it can handle thousands of connections without creating a separate thread for each one.

Why is this important?​

Performance: async code keeps websites responsive.

Scalability: async servers (like Node.js) handle many users efficiently.

Transferable Skill: frameworks like React, Next.js, and libraries like Axios rely heavily on promises and async/await.

User experience: async programming enables progress spinners, real-time updates, and background work without freezing the UI.

info

Event handlers, addEventListener(), are a form of asynchronous programming. You provide a function (the event handler) that will be called, not right away, but whenever the event happens.

Call Stack​

call stack keeps track of the current function

The call stack is the mechanism the JavaScript engine uses to keep track of the function currently being executed. The call stack is how JavaScript “knows” what function is currently being run and what functions are called from within that function, etc.

It follows a LIFO - Last thing in - First thing out order. The last function that gets called is the first one to finish and be removed.

  1. When a function is called, the engine adds ("pushes") it onto the top of the stack.

  2. If that function calls another function, the new one is pushed on top.

  3. When a function finishes, it is removed ("popped") from the stack, and control returns to the function below it.

JavaScript has only one call stack (it's single threaded), which means it can do one thing at a time. This is why asynchronous programming (using callbacks, promises, async/await) is important—it lets long-running tasks step out of the stack so the browser doesn’t freeze.

  • When a function is called, the interpreter adds it to the call stack then starts executing the function.
  • Any functions that are called by that function are added to the call stack and run when their calls are reached.
  • When the current function is finished, the interpreter pops it off the stack and resumes execution where it left off in the last code.
const multiply = (x, y) => x * y;

const square = x => multiply(x, x);

const isRightTriangle = (a, b, c) => (square(a) + square(b) === square(c))
