Middleware

Middleware is code that runs between a client HTTP request and the server endpoint. It acts as a checkpoint or filter that can:

  • Intercept and inspect the request

  • Verify credentials

  • Enforce access rules

  • Modify or reject the request before it reaches the server endpoint

tip

Middleware is where authorization checks happen — it ensures that only permitted users can reach certain parts of the application.

middleware executes before a request reaches the route handler

Access Control​

Middleware is often used in web applications to:

  • Verify tokens or sessions (authentication)

  • Check user roles or permissions (authorization)

  • Reject unauthorized requests early

  • Allow authorized requests to continue

If a request is authorized, we call next() to continue to the server endpoint. If not authorized, return with a 403 status and/or redirect to another route.

The middleware.ts file was renamed to proxy.ts with version 16 of Next.js. (released 10/21/25 )

Middleware setup​

In a Nextjs application, we set up middleware by creating a file called middleware.ts at the project root and including a middleware() function.

We can implement authorization and protecting routes with middleware. The middleware function can check if the user is authenticated before the request is forwarded to the server endpoint.

middleware.ts
const { auth } = NextAuth(authConfig);

const middleware = async (request: NextRequest) => {
    const { pathname } = request.nextUrl;
    const session = await auth();
    const isAuthenticated = !!session?.user;

    const publicPaths = ["/", "/show-item", "/show-items", "/api/items"];

    if (!isAuthenticated && !publicPaths.includes(pathname)) {
        return NextResponse.redirect(new URL("/", request.url));
    }

    return NextResponse.next();
 
};

export const config = {
  matcher: [
    "/create-item/:path*",
    "/update-item/:path*",
    "/delete-item/:path*",
  ],
};

The middleware ensures that only authenticated users can reach certain reoutes.
If the user isn't logged in, they are redirected to the login page. Here's a breakdown:

  1. auth() is a NextAuth helper that provides access the current user session. On a match with this middleware, auth() is is called before the endpoint.
  2. const isAuthenticated = !!session?.user; : session.user holds the session data. If a valid session exists, session.user contains the user object. !! converts it to a boolean value. (If user - true)
  3. If the user isn't logged in, redirects them to /login.
  4. return NextResponse.next(); : continue processing the request - allow to proceed on the route.

Matcher​

In Next.js, the matcher in the middleware function controls which routes the middleware will be applied to. It acts as a filter, ensuring that the middleware only executes for specific paths or patterns. This allows for targeted middleware behavior, such as authentication checks for certain routes or API requests.

You can also check the session in route handlers and server components to see if the user is authenticated to perform this operation.

info

Middleware enforces authorization by acting as a gatekeeper — it intercepts each request, verifies identity and permissions, and only allows authorized requests to proceed on the route.
